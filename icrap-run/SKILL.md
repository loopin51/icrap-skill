# ICRAP 에서 코드 돌리고 검토하기

이 스킬은 **실행 → 검토 → 수정 → 재실행** 을 맡는다. 플랫폼 조작(토큰, 잡 제출·조회·취소, 워크스페이스 시작·정지)은
`icrap` 스킬과 그 클라이언트를 쓴다. 아래에서 다음 이름을 쓴다.

- `icrap` = `python3 ~/.claude/skills/icrap/scripts/icrap.py`
- `ws` = `python3 ~/.claude/skills/icrap-run/scripts/ws.py`

프로젝트에 설치했다면 `~/.claude/skills` 대신 `.claude/skills` 다. `icrap` 스킬을 아직 읽지 않았다면 먼저 읽는다(토큰 확인, 자원 규칙).

## 1. 어디서 돌릴지 고른다

| 상황 | 경로 |
|---|---|
| GPU 학습, 몇 분 넘게 걸리는 실행, 워크스페이스가 없음 | **배치 잡**(기본) |
| 몇 분 안에 끝나는 확인, import·형상 오류 잡기, 짧은 반복 디버깅 | 실행 중인 **워크스페이스**가 있으면 워크스페이스 |
| 비공개 저장소이거나 push 할 수 없는 코드 | 워크스페이스만 가능(잡은 공개 저장소의 push 된 커밋만 돌린다) |

- 배치 잡은 워크스페이스 없이 끝까지 된다. 결과 확인은 로그 API(`icrap logs`)로 한다.
- 워크스페이스에서는 **긴 학습을 돌리지 않는다.** `ws run` 은 항상 시간 제한(기본 540초)을 두고, 넘으면 잡으로 보낸다.
- 어느 쪽이든 로컬에서 먼저 할 수 있는 확인(문법, 작은 입력으로 CPU 실행, 단위 테스트)은 로컬에서 끝내고 보낸다.

## 2. 배치 잡 경로

### 보내기 전에

1. `icrap me` 의 `할 수 있는 일` 에 `잡 제출·취소` 가 있는지 확인한다. 없으면 사용자에게 관리자에게 쓰기 토큰을 요청해
   `icrap login` 으로 입력하라고 알리고(`icrap` 스킬 0절), 그동안 워크스페이스 경로를 쓰거나 멈춘다.
2. 잡은 **원격 저장소의 push 된 커밋**을 clone 한다. 로컬 변경을 커밋하고 push 해야 하는데, **push 는 사용자 확인 뒤에** 한다.
   기본 브랜치를 건드리고 싶지 않다면 작업 브랜치(예: `icrap/<주제>`)를 제안한다. 제출할 때 `--ref` 에는 그 커밋 SHA 를 준다.
3. 처음 돌리는 코드는 **짧은 시험 실행**(에폭·스텝을 줄인 것, 예: `--max-steps 50`)을 먼저 보낸다. 환경·경로·GPU 사용을
   몇 분 안에 확인한 뒤 본 실행을 보낸다. 본 실행이 몇 시간짜리면 시험 실행 없이 보내지 않는다.
4. **잡의 성공·실패는 명령 전체의 마지막 종료 코드로 정해진다.** 확인용 명령을 앞에 붙일 때는 `&&` 로 잇고,
   본 명령(학습) 뒤에는 `;` 로 아무것도 붙이지 않는다. `python train.py; ls "$RUN_DIR"` 는 학습이 실패해도 `완료` 가 된다.
   결과 파일 목록은 붙이지 말고 끝난 뒤 로그·지표로 확인한다.
   좋은 예: `nvidia-smi -L && python train.py --epochs 3 2>&1 | tee -a "$RUN_DIR/stdout.log"`
5. 명령 끝에 `2>&1 | tee -a "$RUN_DIR/stdout.log"` 를 붙인다. 로그 API 는 가장 최근 실행의 파드 로그만 주므로,
   선점으로 다시 실행돼도 전체 기록이 `/shared` 에 남게 한다. 명령은 `bash -o pipefail` 로 실행되어 종료 코드가 유지된다.
6. 검토할 수 있게 코드가 찍게 한다: 시작할 때 장치(`torch.cuda.is_available()`, GPU 이름), 주기적으로 스텝·loss·처리 속도,
   끝날 때 최종 지표. 지표는 `$RUN_DIR/metrics.json` 같은 파일로도 남긴다(체크포인트도 `$RUN_DIR`).

### 보내고 기다린다

```bash
icrap submit --name <주제>-r1 --repo <공개 https 저장소> --ref <커밋 SHA> --gpus 1 \
  --command 'python train.py --max-steps 50 2>&1 | tee -a "$RUN_DIR/stdout.log"'
icrap wait <주제>-r1 --timeout 540          # exit 0 완료 · 3 실패 · 그 밖은 아직 진행 중
icrap logs <주제>-r1 --tail 200             # 실행 중에도 읽을 수 있다
```

- 반복할 때마다 이름을 바꾼다(`-r1`, `-r2` …). 같은 이름은 재시도로 처리되어 새 잡이 생기지 않는다.
- 팀마다 동시에 도는 잡은 2개까지다. 반복 실험을 한꺼번에 여러 개 던지지 말고, 앞 결과를 보고 다음을 보낸다.
- 오래 걸리면 `wait` 를 끊어 부르면서 중간 로그를 본다. 처음 몇 스텝에서 이미 틀린 것(loss 가 NaN, GPU 미사용)이 보이면
  사용자에게 알리고 **확인을 받아** 취소한다(`icrap cancel`).
- `queued` 는 정상 대기다. 순번·사유를 사용자에게 알리고 기다린다.

### 실패했을 때 어디를 보나

`icrap jobs <이름>` 의 `failure` 로 먼저 나누고, 해당 컨테이너 로그를 읽는다.

| failure | 볼 로그 | 흔한 원인 |
|---|---|---|
| `clone` | `icrap logs <이름> --container git-clone` | 저장소가 비공개, ref 를 push 하지 않음, SHA 오타 |
| `exit`, 사유 `uv 준비 실패` | `--container uv-install` | `uv.lock` 이 `pyproject.toml` 과 어긋남, 패키지 해석 실패 |
| `exit`, 사유 `종료 코드 N` | `--container main`(기본) | 트레이스백. **맨 아래 예외와 그 직전의 내 코드 줄**을 찾는다 |
| `oom` | `main` 의 마지막 부분 | 배정 메모리 초과(GPU 1장 잡 24GiB). 배치 크기·worker 수·데이터 적재 방식 |
| `evicted` | `jobs` 의 `reason` | `/workspace` 200GiB 초과. 큰 파일을 `$RUN_DIR` 로 |
| `deadline` | `main` 의 마지막 진행 | 72시간 초과. 체크포인트에서 이어 가게 나눈다 |

환경 단계에서 실패하면 `main` 은 시작하지 않으므로 `icrap logs` 가 "컨테이너가 아직 시작 전"이라고 답한다. 그때는 `uv-install` 을 읽는다.

## 3. 워크스페이스 경로

`ws` 는 워크스페이스에 SSH(`coder ssh`)로 붙는다. 공개 주소 `https://coder.blueodor.xyz` 가 기본이라 Tailscale 이 없어도 된다.
`coder` CLI 설치와 로그인은 사용자가 자기 터미널에서 한 번 한다(`icrap` 스킬 reference.md "coder CLI 준비").

1. 먼저 `ws check` 를 돌린다. 로그인 안내(종료 코드 3)가 나오면 그 안내를 사용자에게 그대로 전하고 기다린다.
   종료 코드 4 는 ICRAP 계정이 정지·만료돼 Coder 가 막은 것이다. 우회하지 말고 관리자에게 문의하라고 알린다.
   **Coder 세션 토큰을 대화창에 붙여 달라고 하지 않는다.** 세션 토큰은 워크스페이스 셸 권한이다.
2. 워크스페이스 이름은 `ws check` 나 `icrap workspaces` 로 본다. 정지돼 있으면 사용자에게 알리고 `icrap ws-start <이름>` 으로
   켠다(30초 안팎, `workspaces:write` 쓰기 토큰 필요). 쓰기 토큰이 없으면 사용자에게 포털에서 켜 달라고 한다.

```bash
ws check                                      # coder CLI·로그인·내 워크스페이스 상태
ws info <워크스페이스>                        # 파이썬·torch·GPU·메모리·디스크 확인(처음 한 번)
ws push <워크스페이스>                        # 현재 git 저장소를 ~/icrap-run/<저장소 이름>/src 로 보낸다
ws run  <워크스페이스> -- python train.py --max-steps 20
ws run  <워크스페이스> --timeout 300 -- pytest -x -q
ws exec <워크스페이스> --cwd /shared/users/<내 이름> -- 'ls -la'    # 아무 디렉터리에서 명령(기본 홈)
ws put  <워크스페이스> ./config.yaml '~/icrap-run/<저장소 이름>/src'  # 파일·디렉터리 하나 보내기
ws pull <워크스페이스> '~/icrap-run/<저장소 이름>/src/out' ./remote-out   # 결과물 가져오기
```

- `push` 는 `git ls-files` 기준으로 보낸다. `.gitignore` 에 든 데이터·체크포인트·`.venv` 는 가지 않는다(200MiB 넘으면 멈춘다).
  보낼 때마다 원격 `src` 를 새로 만든다. **결과물은 `src` 안에 두면 다음 push 에 지워진다.** 남길 것은 `pull` 해 오거나
  `/shared/users/<내 이름>/` 으로 옮긴다.
- `run` 은 `src` 에서 실행하고 출력을 `~/icrap-run/<저장소 이름>/logs/` 에도 남긴다. 종료 코드는 그대로 돌아오고 `124` 는 시간 초과다.
- 파이썬은 워크스페이스의 conda(`~/miniforge3`, Python 3.12)다. **torch 는 기본으로 없다.** `ws info` 에 `torch: 없음` 이면
  설치(수 GB)를 사용자에게 먼저 묻고, 아니면 배치 잡 경로로 간다(잡 이미지에는 torch 가 있다).
  uv 프로젝트면 처음 한 번 `ws run <워크스페이스> -- 'pip install -q uv && uv sync'` 로 환경을 만든다.
- `exec` 도 `run` 처럼 시간 제한(기본 540초) 안에서 돌고 종료 코드를 그대로 돌려준다. 파일을 지우거나 덮어쓰는 명령,
  `/shared` 에서 쓰는 명령은 사용자 확인 뒤에 한다.
- 워크스페이스 안에 백그라운드 프로세스(`nohup`, `&`)를 남기지 않는다.
- GPU 워크스페이스는 사용자 본인의 GPU 다. 다른 사람이 쓰는 자원이 아니어도, 확인이 끝나면 오래 붙잡지 말라고 알려 준다.

## 4. 결과 검토

실행이 끝나면(성공이든 실패든) 로그와 결과물을 **직접 읽고** 판단한다. "완료" 상태만 보고 성공이라고 하지 않는다.

1. **정말 끝까지 돌았나**: 종료 코드, 마지막 줄, 기대한 스텝·에폭 수, 결과 파일(`metrics.json`, 체크포인트)이 생겼는지.
2. **의도한 장치에서 돌았나**: GPU 잡인데 `cuda: False` 거나 장치 로그가 없으면 CPU 로 돈 것이다. 이미지의 torch 대신
   CPU 용 torch 를 설치했는지(uv 프로젝트의 의존성) 본다.
3. **수치가 정상인가**: loss 가 NaN·inf 가 아닌지, 줄어드는지, 정확도가 우연 수준에 머물지 않는지, 검증 지표가 학습 지표와
   지나치게 벌어지지 않는지. 처리 속도(it/s, 샘플/s)와 남은 시간을 계산해 72시간 한도와 비교한다.
4. **경고**: DataLoader worker 경고, deprecated, 정밀도·장치 불일치, 메모리 경고. 결과에 영향이 있는 것만 짚는다.
5. **재현성**: 어떤 커밋(`ref`, `$RUN_DIR/commit.txt`)·명령·자원으로 돌았는지.

고칠 것이 있으면 로컬에서 고치고 → (잡이면 커밋·push 뒤) 이름을 바꿔 다시 돌린다. 같은 오류가 두 번 반복되면 멈추고
지금까지 확인한 것을 사용자에게 보고한다. 원인을 추측으로 단정하지 않는다.

### 보고

사용자에게는 다음을 짧게 알린다.

- 무엇을 돌렸나: 경로(잡/워크스페이스), 잡 이름 또는 워크스페이스, 커밋, 명령, GPU 장수
- 결과: 상태, 핵심 지표와 그 근거가 된 로그 줄
- 문제와 고친 것, 아직 확인하지 못한 것
- 다음 제안(본 실행, 하이퍼파라미터 변경 등)과 결과물 위치(`/shared/runs/<내 이름>/<잡 이름>/`)

## 하지 않는 일

- 사용자 확인 없이 push, 잡 취소, 워크스페이스 정지, 큰 패키지 설치를 하지 않는다.
- 남의 잡·`/shared` 의 남의 폴더를 건드리지 않는다.
- 토큰 원문을 출력·저장·커밋하지 않는다(`icrap` 스킬 0절). Coder 세션 토큰(`~/.config/coderv2/session`)은 읽지도 않는다.
- `coder login`·`coder logout`·`coder tokens create` 를 대신 실행하지 않는다. 로그인 문제는 사용자에게 안내한다.
- 실패를 감추려고 테스트·검증 코드를 약하게 고치지 않는다.
